# Security Monitoring

```text

The attackers never sleep,so monitoring is crucial.
We usually monitor all entry points
-logins, public facing stuff, data storage location, remote access.

This enables us to react to security events by
restricting account access,firewall rulebase, and do more scanning.

Usually there are status dashboards for these monitoring systems.


```
## Monitoring Computing Resources

```text

Systems are often monitored to:

check authentication, logins from strange places.
Server monitoring, service activity,backups, and software versions.

Applications are monitored to:

Improve availability and uptime.
Data Transfers to know when data changes rate of transfers.
Usually there are security notifications so that the developer knows when something happens.

Infrastructure are monitored to:

Check remote access systems - employees, vendors, guests
Firewall and IPS reports - increase or type of attack

```
## Log aggregation

```text
SIEM or SEM (Security Information and Event Manager)
This is used to consolidate many different logs to a central database so you can see what's going on.
This can include Servers,firewalls,VPN concentrators,SANs, cloud services.


This makes it easy to make reports because everything is aggregated into one place.

Correlation between diverse systems, view authentication and access, track application access, and measure and report on data transfers.

```
## Scanning

```text
Many business have a system in place to actively scan systems and devices to check where things are and how they're doing and what version of things they are running.

This could be operating system versions, device driver versions, installed applications, potential anomalies.

The scanning process grabs a lot of information and its often given to a database where you can later make reports with.

```

## Reporting

```text
After gathering data using scanning devices, usually have the ability to create "Actionable" reports.

This information can also be used to grab status information including the number of devices up to date/ compliance and know which devices are running older operating systems.

This information can also be used to determine the best next steps, how many systems are vulnerable and what to do knowing what we know right now.
```

## Archiving

```text

It takes about 9 months for a company to identify and contain a breach.

Access to data is critical, it is often archived for a long time.

This may be due to a mandate or organizational requirements.

```

## Alerting

```text
Usually we set up alerts to give

Real-time notifications of security events, increased authentication errors,Large file transfers

We can keep people in the loop by sending alerts to them as well.

Notification methods include:
    -SMS/text
    -Email
    -Security console / SOC
```

## Alert response and remediation

```text
These are options to do in response to an alert.

Quarantine - A foundational security response to prevent a potential security issue from spreading.

Alert Tuning - A balancing act, often tuning is to prevent false positives and false negatives.

An Alert should try to be accurate and tuning should be ongoing hopefully getting better as time goes on.

```

# Security Tools

```text

On your Enterprise network there are probably a bunch of different security tools you're using.

    Often NIST is used by these tools to identify and act on the same criteria.
    This is usually to validate security configurations, confirm patch installs, scan for security breach.

    This means that we can actually make these tools coordinate the detection and removal of detected stuff.

```

## Using SCAP(Security Content Automation Protocol)

```text
This is usually more focused on configuration compliance.

SCAP content can shared between tools, useful in large environments, since it can get a hard to manage.

This specification standard enables automation (even between different tools)

Automation types:
    - Ongoing monitoring
    - Notification and alerting
    - Remediation of noncompliant systems
```

## Benchmarks

```text
Benchmarks are useful because we always want to apply security best practices to everything.
    - Operating systems, cloud providers, mobile devices,etc.
    - The bare minimum for security settings.

Eg: issuing a Mobile device.
    - disable screenshots, screen recordings, prevent voice calls when locked, and force encryption backups BY DEFAULT.
```

## Agent/agentless

```text
Check to see if the device is in compliance, install a software agent onto the device onto the device. Run an on-demand agentless check.

Agents can usually provide more detail.
This can be through always monitoring for real-time notifications
Must be maintained and updated

Agentless runs without a formal install, performs the check, then disappears, Does not require ongoing updates to an agent, will not inform or alert if not running.
```

## SIEM (Security information and event management)

```text

This is a system that collects logs of security alerts in real time.

It aggregates the logs and is also used for long-term storage.

Data correlation, Link diverse data types.

Forensic analysis, gather details after an event.

```

## Anti- virus and Anti-malware

```text
Anti-virus is the most popular terms for a software that stops spyware,ransomware,fileless malware.

make sure your systems are using a anti-malware software, the names are interchangeable.
```

## Data Loss Prevention (DLP)

Know where your data is stored so you can know where data could leak through, there can be so many destinations (DLP is a solution for monitoring this)

## SNMP (Simple Network Management Protocol)

Inside a MIB metrics are monitored, OIDs(Object identifiers) are found in the MIB.

Request statistics from a device, poll devices at fixed intervals.


## SNMP traps

Configure the policy so a SNMP trap can be configured on the monitored device.

Alerts will go off after a certain threshold.


## NetFlow

Gather traffic statistics from all traffic flows
Probe and collector, probe watches network communication and the summary records are sent to the collector. 

## Vulnerability scanner

Usually minimally invasive,unlike a pentest.

Port Scan - think nmap

Identify systems - think footprinting

Test from inside and outside.

Gather as much info as possible
