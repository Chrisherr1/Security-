# Scripting and Automation

```text
Scripting automates tasks you'd normally do manually, so problems can get resolved without you being there (no 3am phone calls).

It's fast, it runs as fast as the system it's on, with no typos or human delays.

It can find and fix problems before anyone even knows there was an issue.
```

## Benefits

```text
Saves time
    - Runs whenever needed, over and over, with no human intervention.

Enforces security baselines
    - eg: a script watches a folder for new security patches and automatically deploys them to every system that needs it.

Standard infrastructure configurations
    - eg: default router configs, firewall rules for a new remote site.
    - You know every device gets the correct config with all the required security controls.

Secure scaling
    - When scaling a cloud app up/down, the script adds the firewalls and security devices along with the servers and databases.

Employee retention
    - IT staff can move away from boring repetitive tasks and work on more interesting things.

Reaction time
    - Constant monitoring 24/7, eg: disk space is low, the script clears out temp files to keep the server running.
```

## Use cases

```text
User provisioning (onboarding/offboarding)
    - Create the account, assign groups, home directory, printer, email access.

Guardrails
    - Automated checks on what a human is inputting so it doesn't cause a problem.
    - eg: a tech accidentally tries to delete a huge part of a server, the guardrail blocks it.

Security groups
    - Automatically add/remove users from groups.
    - Alert if someone gets added to the administrator group.

Ticketing
    - Turn a help desk email into a ticket and assign it to the right person.

Escalation
    - The script tries to fix the problem first, if it can't it escalates to the on-call technician.

Enabling/disabling services
    - Turn a service on for a set time, then turn it off automatically.

Continuous integration and testing
    - Developers automatically push code updates out to systems.

Integrations and APIs
    - Scripts talk directly to a device's API (cloud, firewall, etc.) instead of logging in and clicking around.
```

## Important considerations

```text
Complexity - scripts interact with lots of systems, so they need a lot of testing.

Cost - someone has to write the scripts, that takes time and money.

Single point of failure - if the script breaks, everything relying on it could have a problem.

Technical debt - scripting around the symptoms instead of fixing the root problem just hides it and makes it worse.

Ongoing supportability - OS or language changes mean someone has to keep updating the scripts.
```
