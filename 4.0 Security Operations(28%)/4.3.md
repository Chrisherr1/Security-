# Threat intelligence

## THE FOUR THREAT FEED SOURCES

```text
1. OSINT (Open Source Intelligence)
    - Publicly available, free, anyone can access it
    - Hacker discussion groups, social media, security researcher posts
    - Government: public hearings, reports, websites
    - Public commercial data: financial reports, databases

2. PROPRIETARY / THIRD PARTY
    - Paid threat intelligence services
    - Key advantage: visibility across many organizations at once
    - Spot attack trends early and warn you before the threat reaches you
    - May combine public data, declassified info, and their own research

3. INFORMATION SHARING ORGANIZATIONS
    - Groups of organizations pooling threat data with each other
    - Example: Cyber Threat Alliance (CTA)
        Members submit threat data
        Alliance validates each submission
        Scores severity
        Puts it in a standard format
        Shares with all members
    - ISACs (industry specific sharing centers) also fit here

4. DARK WEB
    - Overlay network that uses the internet for transport
    - Requires special software to access (example: Tor)
    - Contains hacking group forums, their tools and techniques
    - Marketplaces selling stolen data (example: credit card numbers)
    - Monitor it for your organization's name to catch leaks early
```

---

## EXAM SCENARIO MATCHING

```text
- Paying a vendor that watches attacks across many customers = Proprietary / third party
- Peers validating and scoring shared threat data = Information sharing organization
- Searching government reports or social media = OSINT
- Watching hacker forums for your company's leaked data = Dark web monitoring
```

# Pentesting

## What penetration testing is

```text
Simulating an attack on your own systems.
Like a vulnerability scan, except you actually exploit the vulnerabilities to see if you
can get in.
Often done on a regular schedule, and some industries are required to do it.
NIST reference: SP 800-115, the Technical Guide to Information Security Testing and
Assessment.
```

---

## Rules of engagement (know this cold)

```text
A formal written document, agreed on before testing starts, that sets the scope and
purpose of the test. It covers:

- When testing is allowed, such as only after 6:00 PM local time
- The type of test: on-site physical breach, internal, or external
- Which systems can be tested, such as specific IP address ranges, and which are out of
  scope
- Emergency contacts
- How to handle sensitive data uncovered during the test

The goal is to test the right systems while keeping production running.
```

---

## Exploiting vulnerabilities

```text
The goal is to gain access through known vulnerabilities. If you can do it, an attacker
can too.
Common methods include password brute force, social engineering (even over the phone),
database injection, and buffer overflows.
Exploits can crash systems. A buffer overflow used for privilege escalation might take
down the OS, which is why the rules of engagement flag critical systems.
```

---

## After gaining access (three terms to know)

```text
Lateral movement: moving from one device to another inside the network.

Persistence: making sure you can get back in without relying on the original
vulnerability, since it might get patched.
    Methods include creating a backdoor, adding your own account, or changing default
    passwords on an existing account.

Pivot: firewalls block you from outside, but once you're inside, you use that first
system as a relay or proxy to reach other internal systems.
```

---

## Responsible disclosure and bug bounties

```text
Responsible disclosure: a researcher reports a vulnerability privately to the vendor. The
vendor fixes the code, tests it, and releases a patch, which can take weeks or months.
Only after the patch is out does the vulnerability go public and get added to the CVE
list.

Bug bounty: a reward, usually funded by the software developer, paid to whoever finds and
reports a vulnerability. It follows the same order: find, report, fix, then publish.
```

---

## How the exam tests this

```text
Expect scenario questions where you match a description to a term:

- A document listing allowed IP ranges, testing hours, and contacts is the rules of
engagement.
- Moving from one compromised device to another is lateral movement.
- Adding an account or backdoor to keep access is persistence.
- Using a compromised host as a relay to reach internal systems is a pivot.
- A vendor paying outside researchers for finding flaws is a bug bounty.
- Finding vulnerabilities without exploiting them is a vulnerability scan. Exploiting
them is a penetration test.
```

## Vulnerability Remediation

```text

In the majority of cases where a vulnerability has been identified, there's usually a patch that fixes it.

Security patches are usually scheduled monthly or quarterly

If a vulnerability is unusually bad and urgent a unscheduled patch is often sent.

This is an ongoing process, the patches are constant.
```

## Insurance

```text
Cybersecurity insurance coverage is often bought to reduce lost revenue, data recovery costs, or money lost to phishing.

Often doesn't cover everything. Intentional acts,funds transfers,ect.

Ransomware has increased in popularity of cybersecurity liability insurance, because it can be used to recover the money you lose giving it to the attacker.
```

## Segmentation

```text
Another way to mitigate any type of attack,is to limit the scope of of the attack.

One way to do that is through segmentation. You can separate devices into their own networks via VLANs.

This may not prevent the attack but it limits the scope of how bad it could be.

It can also be helpful when, you cant patch something.. You can disconnect the effected application/device and put it in a private network with itself, so it can only communicate with itself.

It can also be helpful to use internal NGFWs to block any unwanted traffic betwen VLANs to identify malicious traffic that shouldnt be communicating between the VLANS.

```

## Validation of remediation

```text
Assuming a patch was rolled out because of a vulnerability, we have to check if it acutally fixed the vulnerability and if we patched all systems.

Common practice is to rescan, by preforming an extensive vulnerability scan. Conducting on audit checking if all systems were updated.
Manually confirming the security of the system.
```
## Reporting

```text
You need a reporting system to check out what new vulnerabilities your systems have been exposed to and you'll need to be informed of any new vulnerbaility that may come out.

Automation is manditory, to do this process.

Continous reporting is needed for finding vulnerabilities and keeping track of the number of devices you're patching or dealing with.
```
