# Identity and Access Management 


```text
The process of giving the right people at the right times to provide them the access that they need is what identity and access management or IAM is all about.
```


## Identity and Access Management (IAM)

```text
Identity lifecycle management, every entity (Human and non-human) gets a digital identity.

By doing so this allows us to do access control, where entity only get access to what they need.

By doing so also it allows us to implement authentication and authorization, to have entities prove who they claim to be.

This system also allows us to track an entity's resource access, and may be a regulatory requirement.
```

## Provisioning / de-provisioning

```text
This IAM service often involves creating and removing users.

Often common reasons for creating new users or removing users would be hiring,promotions, job separation, etc..

An important part of the IAM process is having admin inaccessible to any user and have an initial checkpoint to limit access.
```

# Permission assignments

```text
Each entity gets limited permissions, just enough to do their job.

Storage and files can be private to a user.

No privilege access to the operating system.

```

## Identity proofing

```text
Basically verifying who the user might be.

There should be a formal process to verify that a user is really who they say they are.

This process is referred to as resolution, and it's important step to ensure that we are not assigning rights and permissions to someone who should not be on this network.

It's also important that we're able to obtain additional validation from the user.

This means the user needs to provide something they know such as a password and/or security questions.
```

## Attestation

```text
Attestation is periodically reviewing accounts and their permissions to confirm they're still appropriate.

Verifying a person's identity with additional details is part of identity proofing.

This is often done through government documents like a passport or driver's license, and might include a in person meeting.

There are some automated verification options as well that check at a user's credit report and ask personal questions to see if it's actually them.
```

## User walkthrough

```text
When a user needs to gain access to a resource on the network, they need to provide some type of authentication.

This usually begins with the client sending information into a central point that can be used for authentication.

This might be on a VPN concentrator or logging into an Active Directory infrastructure.

The user will provide authentication details, such as a username and password. And there’s usually a centralized authentication server that will be used to validate that information. 

If that login information is correct, the authentication server will send back a notice saying that those credentials have been approved, and the user is then able to gain access to that resource.
```

## SSO or Single Sign-On

```text
This is the process where you would login in one time on the network. And from that point forward you gain access to all the resources that you might need regardless of where those resources may be located.

WITHOUT SSO,

every time you would need access a new printer or access a different share on the network, you would provide your username and password every time.


This type of login is usually on a timer. So once you log in the first-time, you may have access to all of the resources you need for a set time (eg: 24 hours).

After that period, you would need to provide authentication again for the SSO to apply.

This means that your login credentials and the underlying authorization process have to support SSO.
```

## LDAP (Lightweight Directory Access Protocol)

```text
This is a protocol for accessing large directories of data on a network.

It is based on the X.500 Standard set by the International Telecommunication Union(ITU).

Active Directory is a common LDAP directory

LDAP uses port 389

Secure LDAP uses port 636
```

## Distinguished Name (DN)

```text
This is written in as an attribute

CN=Printer01, OU=Accounting, O=Acme, C=US
CN = Common Name
OU = Organizational Unit
O = Organization
C = Country
```

## Directory Information Tree (DIT)

```text
The hierarchy that organizes everything,

Country,then organization, then OU, then Individual objects.

Container object hold other objects; leaf objects are individual items at the end of the branches (users,devices).
```

## What is SAML ? (Security Assertion Markup Language)

```text
Open standard for authentication and authorization

Not originally designed for mobile apps,and its only real downside.

```

## The SAML authentication flow

```text

1. User accesses the application URL.

2. Sends signed/encrypted SAML request,redirects user to the Identity Provider (IdP).

3. User Logs in 

4. The IdP checks if its successful and if it is a SAML token is generated.

The user is given the SAML token and now...

5. User presents SAML token

6. SAML token verified, access granted

```

## OAuth

```text

This is an Authorization framework and determines what a user will be able to access.

Created by Twitter,Google, and many others.
Very supported.

This though is not an authentication protocol.

OpenID connect handles the single sign-on authentication

OAuth provides authorization between applications.

```

## Federation 

```text

Provides network access to others, this is a way to provide SSO and more to partners,suppliers, customers, etc.

Third-parties can establish a federated network, This can be used to authenticate and authorize between two organizations.

This can also make it possible to login to a place using your facebook,google,credentials.

```

This is often determined by what is at hand and not what you'd like.

# Access Control

```text

Access control is the process of enforcing policies to ensure only authorized people are allowed to access data.

Individual or groups.

```

## What are my options?

## 1.Least privilege

```text
This is when rights and permissions should be set to the bare minimum. The user is only given enough to do their job.

All user accounts must be limited as well as applications.

We wouldn't allow users to run with administrative privileges. By not allowing this by default it limits the scope of malicious behavior.

```
## 2.Mandatory Access Control (MAC)

```text
This is where the operating system limits the operation on an object. This is usually based on security levels.

Every object gets a label.
    - Confidential,secret, top secret,etc

Labeling of objects uses predefined rules
    - The administrator decides who gets access to what security level, Users cannot change these settings.
```

## 3. Discretionary Access Control (DAC)

```text

This is used in most operating systems.

Most common kinda like google docs/google drive file access.

Very flexible since the user sets what the other users can do but very weak security wise because it can get a little crazy as you can imagine.

```

## 4. Role-based access control (RBAC)

```text
This is a access control based on the role you are given and based on your role you will gain access that way.

```

## 5. Rule-based access control

```text
This is where access is determined through system-enforced rules and admins are responsible for configuring permissions.

The rule is associated with the object, it is often a way of protecting a certain asset.

Think of the process of accessing secret data, you kinda need to jump through some rules/hoops to get to it.

eg: Access to files are only available from 9-5
```

## 6. Attribute-based access control (ABAC)

```text
With an attribute based access control, users can have complex relationships to applications and data.

Access may be based on many different criteria.

ABAC can consider many parameters, considered a next generation authorization model since aware of context.

usually combined and evaluate multiple parameters. Resource information, IP address, time of day,desired action, relationship to data, etc.
```

# Multifactor Authentication

```text

Multifactor authentication is used to prove who you are and there are often different methods to do so.

Factors that could be used..

1. Something you know
    - password,pin,pattern
2. Something you have
    - Smart card, usb security key, software tokens, phone(SMS)
3. Something you are
    - Biometric authentication
4. Somewhere you are
    - IP address or mobile device location services.

```
# Password Security

```text
Make them long, preferably over 8 characters. (NIST now says only force changes if a password is compromised, but the exam still covers password age/expiration.)

It is really important to use different passwords for each account, so its useful to use a password manager and it's often built-into many operating systems and browsers.

Give people access for a limited time if they need access for a limited amount of time (just-in-time permissions).
```
