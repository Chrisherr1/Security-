# Viruses and Worms

## Virus

```text
- Malware that can reproduce itself
- needs you to execute a program
- reproduces through file systems or the network
- May or may not cause problems
- Anti- Virus is very common
```

### Types of Virus

```text
Program viruses
    - Part of the application
Boot sector Viruses
    - Waits in boot section
Script Viruses
    - runs on the browser
Macro Viruses
    - Common in Microsoft Office

Fileless Virus - stealth attack
    - Does a good job avoiding anti virus
    - operates in memory but never leaves files around to be found

    eg:
        1. User clicks on a malicious website link
        2. Website exploits a Flash/java/Windows vulnerability
        3. Launches powershell and downloads payload in Ram
        4. Runs Powershell scripts and executables in memory
           exfiltrates data, damages files
        5. Adds an auto-start to registry just in case of shut down
```

## Worms

```text
- Self replicate without user intervention
- Uses the network as a transmission medium
- Worms can move freely in network
- Firewalls and IDS/IPS can mitigate many worm infestations
```

```text

    - So they break the safe (Cryptography)

  but that also means that attackers can too.

```

---

## Birthday Attack

```text
- Metaphor : In a class room of 23 students, what is the chance of two students sharing a
  birthday?
                answer: about 50%
                - for a class of 30, the chance is 70%

In the digital world, this is a hash collision.
    - A hash collision is the same hash value for two different plaintexts.
    - Find a collision through brute force

- The attacker will generate multiple versions of plaintext to match the hashes
    - Protect yourself with a large hash output size.
```

---

```text
    - different input data should not create the same hash

```

## Downgrade attack


### SSL Stripping

```text
- Combines an on-path attack with a downgrade attack
- difficult to implement but is very powerful
- attacker might sit in between
- victim's browser page isn't encrypted
- strips the S away from HTTPS
```

#### how it works

```text
Basically, attacker must be already intercepting the user's web traffic. When the user
tries to visit a http site the site itself will try to redirect him to the https version
at which point the attacker can intercept the request and put in their own fake version
of the website to trick the user to give their information through the login etc.
```

#### things that have to be true

```text
You have to try to make the user click on a http version of a website(maybe through
vishing?)

You have to make a fake website a user would fall for to add their login details.

You have to have a server running to grab that data being sent, via your computer

You have to somehow be a man in the middle already.
```

# Password Attacks

## Plaintext / unencrypted passwords

```text
- Just don't store passwords as Plaintext
```

---

## Hashing a password

```text
- We should store a password as a Hash
- Every password will have a different Hash
- No way to reverse engineer to get the password
```

---

## The password file

```text
- different across operating system
```

---

## spraying attack

```text
- Trying to login with most common passwords
    - might get locked out
    - If they don't work they move to the next account
```

---

## brute force attack

```text
- trying every possible password combination until the hash is matched.
- This might take some time
    - A strong hashing algorithm slows things down.
```

### Online

```text
- keep trying the login process
- very slow
- Most accounts will lockout after a number of failed attempts
```

### Offline

```text
- Obtain the list of users and hashes
- calculate the password hash
- compare it to the stored hash
- large computational resource requirement
```

## Radio frequency (RF) jamming

```text
- type of DoS that affects all people

- transmit interfering wireless signal
    - Decrease the signal-to-noise ratio at the receiving device
    - the receiving device can't hear the good signal

- Sometimes not intentional
    - interference,not jamming
    - microwave oven,fluorescent lights

- Jamming is intentional though..
```

### Ways to jam

```text
- sending legitimate constant,random bits through the network
- Data send at random times - random data and legitimate frames
- reactive jamming - only when someone else tries to communicate

- needs to be somewhere close

- time to go fox hunting
    - directional antenna
```

# Application Attacks

## Injection Attacks


## Buffer overflows

```text
- You add information into a particular area in memory meant for
  a variable but you're adding more information than that variable can
  hold.

- so the memory spills over to the next buffer

- due to developers not performing bounds checking
- relatively difficult exploit
- crashes the application usually

- if attacker find a buffer overflow that is REPEATABLE.
  then now we have a problem
```

---

## Replay Attack

```text
- some applications will allow an attacker to grab information from the
  network directly or from the victim's computer and REPLAY that information
  to the server to gain addition access to the application.

- Need access to the raw network data.
    - Network tap,ARP poisoning, malware on victim computer

- The gathered information may help the attacker
    - Replay the data to appear as someone else.

this is not an on-path attack
```

## privilege escalation

```text
- Gain higher level access to a system
- might be a bug or design flaw

- higher-level access means more capabilities

- common attack type
- high priority

- horizontal privilege escalation
     user A can access user B resources
```

### Mitigating privilege escalation

```text
- Patch quickly
    - fix vulnerabilities
- Updated anti virus / anti-malware software
    - block known vulnerabilities
- Data Execution Prevention
    - only data in executable areas can run
- Address space layout randomization
    - prevent a buffer overrun on a specific memory
```
